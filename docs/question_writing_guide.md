# 문항 작성 가이드

`generate_questions.py`가 자동으로 따르는 규칙을 사람이 읽을 수 있는 형태로
정리한 문서. 문항을 손으로 검수하거나, 프롬프트를 수정할 때 이 기준으로
판단한다.

## 1. 톤 & 소재

- 캐주얼하고 일상적인 소재만 사용: 여행, 음식, 친구, 루틴, 물건, 상황 비유
- 설문지처럼 딱딱한 문장 금지. 친구한테 묻듯이 자연스러운 구어체
- 특정 계층(고가 소비, 특정 외모)을 전제하지 않기 — 누구나 답할 수 있는 상황이어야 함
- 이모지·은어는 과하지 않게, 있어도 되고 없어도 됨

## 2. 형식 4종과 각각의 규칙

| 형식 | 옵션 수 | 규칙 |
|---|---|---|
| `ab_dual` | 2 | 서로 완전히 배타적인 두 문장 |
| `four_choice` | 4 | 한쪽 극에서 반대쪽 극으로 점점 이동하는 그라데이션. weight도 양끝 1.0, 중간 0.4로 강도 반영 |
| `metaphor` | 3~4 | 자신/하루/기분을 무언가에 빗대기 (날씨, 악기, 신호등 등) |
| `object_choice` | 3~4 | 구체적 실물/장소/브랜드성 대상 중 선택 (여행지, 선물, 메뉴) |

## 3. 특성(trait) 연결 규칙

- 문항 하나가 반드시 **주 특성(primary trait)** 하나에 강하게(0.7~1.0) 연결
- 자연스럽게 걸치는 **부수 특성**이 있으면 0.2~0.5로 추가 연결 (없으면 생략 가능)
- 없는 관계를 억지로 만들지 않기 — 걸치는 게 진짜 없으면 주 특성만 연결
- bipolar 특성은 `pole` 값이 **반드시 `traits_seed.json`의 pole_left/pole_right 영문 key**여야
  함 (한글 라벨 절대 금지 — 실제로 한 번 발생했던 버그, `load_bank_to_db.py`가 자동으로 검증해서 걸러냄)
- independent 특성(RIASEC 등)은 `pole`을 null로 두고 weight만 부여

## 4. 절대 금지 (사람 검수 시 최우선 체크)

다음 의도가 조금이라도 감지되면 그 문항은 즉시 폐기:

- 우울/무기력감의 정도·빈도
- 불안/걱정의 정도·신체 증상
- 자해·자살 관련 사고
- 식습관 문제(폭식/제한)를 진단적으로 묻는 것
- 지능/IQ (능력검사 영역, 선호도 질문으로 측정 불가능)
- 그 외 임상 선별 도구(PHQ-9, GAD-7, MMPI 등)에서 기원한 문항 구조

라벨을 순화하는 것만으로는 안 됨 — 문항이 임상 선별 도구의 **구조**에서
설계되었는지가 기준. (`FORBIDDEN_KEYWORDS`는 최소한의 자동 스크리닝일 뿐,
사람 검수가 최종 방어선)

## 5. 좋은 문항 vs 나쁜 문항 예시

**좋은 예**:
> "친구가 갑자기 '오늘 처음 가는 동네에서 밥 먹자'고 하면?"
> — 구체적 상황, 캐주얼, 성향이 자연스럽게 드러남

**나쁜 예 (너무 설문지스러움)**:
> "당신은 새로운 경험에 대해 개방적입니까?"
> — 직접 묻는 방식은 사회적 바람직성 편향(social desirability bias)이 커서
>   실제 성향과 답변이 어긋나기 쉬움

**나쁜 예 (임상 뉘앙스)**:
> "요즘 아침에 일어나기가 힘들다고 느낀 적이 며칠이나 되나요?"
> — PHQ-9 스타일 빈도 질문, 절대 금지

## 6. 중복 체크 기준

문자열 유사도(difflib, threshold 0.72)로 1차 자동 스크리닝하지만, 완벽하지
않음. 사람이 볼 때는 "표현만 다르고 내용이 같은지"를 본다:

> "친구들과 왁자지껄 vs 혼자만의 시간" 과 "다같이 모이기 vs 혼자 있기"는
> 표현은 다르지만 사실상 같은 질문 — 이런 건 하나만 남긴다.

향후 문항 수가 많아지면 문자열 유사도 대신 임베딩 기반 유사도로 고도화 권장.
