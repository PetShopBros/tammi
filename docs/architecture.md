# 설계 결정 요약

## 컨셉
듀오링고 구조(온보딩 → 홈 지도 → 세션 카드 루프 → 리캡 → 리텐션 루프)를 차용하되,
"정답"이 없는 자기발견 콘텐츠에 맞게 하트/오답 시스템은 제거하고,
결과는 경쟁(리더보드)이 아니라 "과거의 나 vs 지금의 나" 비교로 대체.

## 문항 <-> 카테고리 관계
문항 하나가 카테고리(특성) 하나에만 속하지 않고, 여러 특성에 서로 다른
가중치로 동시에 기여할 수 있음 (심리측정학의 요인적재 개념).
그래서 DB를 questions - traits - question_trait_links(다대다 + weight)
구조로 설계함. 자세한 스키마는 backend/db/schema.sql 참고.

## 다루는 카테고리 (6개 계열, 22개 결과)
- A. 성격특성: Big Five 5축, MBTI풍(Big Five 재매핑), 에니어그램풍(재미 섹션 분리), 인지스타일
- B. 직업/커리어: RIASEC, 업무가치관, 의사결정스타일, 팀역할유형, 위험감수성향
- C. 관계/커뮤니케이션: 갈등대응스타일, 애정표현방식, 관계편안함경향(애착이론 기반, 라벨 미노출), 커뮤니케이션톤
- D. 라이프스타일: 시간관, 소비성향, 취향지도
- E. 사고방식: 통제소재, 창의성유형
- F. 학습/동기: 학습스타일선호, 학업동기유형, 공부방식, 완벽주의성향(학업), 학습환경선호, 실행스타일

## 명시적으로 제외한 것 (안전 기준)
다음 의도가 조금이라도 감지되는 문항은 만들지 않음:
- 우울/무기력감의 정도·빈도
- 불안/걱정의 정도·신체 증상
- 자해·자살 관련 사고
- 식습관 문제(폭식/제한)를 진단적으로 묻는 것
- 지능/IQ (선호도 검사 방식으로는 측정 불가능한 능력검사 영역)
- 그 외 임상 선별 도구(PHQ-9, GAD-7, MMPI 등)에서 기원한 문항 구조

라벨을 순화하는 것만으로는 문제가 해결되지 않음 — 문항이 임상 선별 도구의
구조에서 설계되었는지가 기준이지, 결과 화면에 뭐라고 표시하는지가 기준이 아님.
`generate_questions.py`에 금지 키워드 필터를 안전장치로 넣어뒀지만, 이건
최소한의 스크리닝이고 사람 검수가 반드시 필요함.

## 문항 형식 4종
1. ab_dual — 둘 중 하나 선택 (지금 프로토타입 기본형)
2. four_choice — 4지선다 (같은 축 안에서 정도 차이 표현 가능)
3. metaphor — 자신을 무언가에 빗대기 (날씨, 악기 등)
4. object_choice — 구체적 대상 중 선택 (여행지, 선물 등)

## 생성 파이프라인
사람이 카테고리별 스펙(정의 + few-shot 예시)을 한 번 설계 →
API가 스펙당 대량 생성 → 중복 스크리닝(문자열 유사도, 추후 임베딩으로 고도화 권장) →
사람이 샘플 검수 → 문제은행에 편입. 900~1000개를 손으로 다 쓰는 게 아니라
스펙 수십 개만 정교하게 설계하는 구조.

## 자동화 범위와 한계
Claude.ai 아티팩트는 브라우저에서만 동작해서 스케줄러(cron)를 못 가짐.
매일 자동 생성이 실제로 동작하려면 이 스크립트를 사용자가 소유한 서버나
클라우드 함수(cron, GitHub Actions scheduled workflow, AWS Lambda + EventBridge 등)에
등록해서 실행해야 함.
